# 第 0 课：先认识实验机器

## 本课目标

完成本课后，你应该能区分三个角色：

- host：实际运行构建工具的 Apple Silicon Mac，架构是 arm64。
- target：交叉编译器生成代码所遵循的平台，本课程是 `x86_64-elf`。
- guest：QEMU 模拟出来、将来真正执行内核的 x86-64 机器。

这三个角色一旦混淆，后续遇到“文件明明编译成功却不能启动”“链接器偷偷带入宿主运行库”之类的问题会很难定位。

## 先做实验

在仓库根目录运行：

```sh
make check-tools
```

观察最后两项：

```text
host architecture:        arm64
compiler target:          x86_64-elf
```

它们不同不是错误，而是交叉编译成立的证据。

## 工具各自负责什么

- `nasm`：把我们早期的 x86 汇编源代码转换成机器码或目标文件。
- `x86_64-elf-gcc`：面向无宿主操作系统的 x86-64 目标编译 C；前缀明确了目标平台。
- `x86_64-elf-ld`：按链接脚本组合目标文件并决定内存地址。
- `x86_64-elf-objdump`：从产物反查节、符号和反汇编，是验证构建结果的重要证据。
- `qemu-system-x86_64`：模拟一整台 x86-64 计算机，而不只是运行一个进程。
- `x86_64-elf-gdb`：暂停 guest，检查寄存器、内存、指令和源码映射。
- `mtools`：无需在 macOS 挂载磁盘镜像就能操作 FAT 文件系统。
