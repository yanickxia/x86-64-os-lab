# 第 7 课：打开 A20，越过 1 MiB 边界

## 先修知识

开始前应理解：

- 实模式地址计算：`segment × 16 + offset`。
- `IN` 从 I/O 端口读入数据，`OUT` 向 I/O 端口写出数据。
- `AL` 是 `AX` 的低 8 位。
- 二进制中的“第 0 位”和“第 1 位”从最低位开始编号。

本课会解释 `IN`、`AND`、`OR` 和系统控制端口 `0x92`。指令语法可查阅 [NASM 与 x86 寄存器入门](reference/assembly-basics.md)，硬件背景可参考 [OSDev Wiki: A20 Line](https://wiki.osdev.org/A20_Line)。

## 本课只引入一个机制

确保物理地址第 20 位能够送到内存系统，使内核将来可以可靠访问 `1 MiB` 以上的内存。

```text
A20 开启：CPU 产生的地址 bit 20 保持原值
A20 关闭：地址 bit 20 被强制清零
```

这不是进入保护模式，也不是分页；它只是决定两段本应不同的地址是否发生别名。

## 1. 为什么有 A20

8086 只有 20 根地址线，能够表达的物理地址范围是 `0x00000` 到 `0xfffff`。但实模式分段公式可以算出更大的值：

```text
ffff:0010 → 0xffff × 16 + 0x0010 = 0x100000
```

在早期机器上，没有第 21 根地址线承载这个结果的 bit 20，因此它会回绕到 `0x00000`。后来的处理器能够访问更多内存，但为了兼容依赖回绕行为的旧程序，主板提供了 A20 gate。

例如：

```text
逻辑计算结果       A20=0 时      A20=1 时
0x000500           0x000500       0x000500
0x100500           0x000500       0x100500
```

A20 关闭时，这两个地址指向同一物理位置；开启后才是两个不同位置。

## 2. 为什么实验要主动制造红灯

当前 QEMU 在 CPU 复位时已经报告 `A20=1`，SeaBIOS 也可能在交给启动扇区前改变它。真实 bootloader 不能把这种初始状态当成保证。

为了得到可重复的红灯，课程脚手架在 `main` 中故意清除端口 `0x92` 的 bit 1：

```asm
in al, 0x92
and al, 0xfc
out 0x92, al
```

`0xfc` 的二进制是 `11111100`，所以这段代码同时清除了 bit 1 和 bit 0。它仅用于教学基线；真实 bootloader 不应先关闭 A20。

运行：

```sh
make check-a20
```

应看到：

```text
A20 check: expected A20=1 after boot code, got A20=0
```

测试会先等待原有的 `Hello` 输出，证明启动代码已经执行到最终循环，再通过 QEMU monitor 读取实际的 `A20` 状态。因此它不会误把复位时的初始值当成你的结果。

## 3. 端口 0x92 的两个相关位

本课使用 System Control Port A：

```text
bit 1 = A20 enable
bit 0 = fast reset
```

目标是把 bit 1 设为 `1`，同时保证 bit 0 为 `0`。不能简单写入一个全新的常量，因为端口中的其他位可能包含我们不应破坏的状态。

正确的读—改—写结构是：

```asm
in al, 0x92     ; 先读取原值
and al, 0xfe    ; 只把 bit 0 清零，避免请求 reset
or al, 0x02     ; 只把 bit 1 置一，打开 A20
out 0x92, al    ; 写回修改后的值
```

逐位理解：

```text
0xfe = 11111110b：bit 0 一定变成 0，其他位保持
0x02 = 00000010b：bit 1 一定变成 1，其他位保持
```

`AND` 和 `OR` 都会修改标志位，但本段代码没有在它们之后读取 `ZF`，所以不会干扰字符串循环中的 `test al, al`；循环每次都会重新设置标志位。

## 4. 练习

修改 `main` 开头的红灯代码，实现上述安全的 A20 读—改—写序列。

保持：

- `main` 位于 `0x7c10`。
- 原有字符串循环仍输出严格的 `Hello`。
- `putc` 位于 `0x7c30`，`message` 位于 `0x7c40`。
- 不要删除脚手架后面的段寄存器、栈、调用和字符串逻辑。

完成后依次运行：

```sh
make check-a20
make check-debugcon
make check-call
make check-segments
make inspect-message
make disassemble-boot
```

## 观察题

1. `ffff:0010` 按实模式公式得到的线性地址是多少？
2. A20 关闭时，`0x100500` 为什么会与 `0x000500` 别名？
3. `and al, 0xfe` 对 bit 0 和其他各位分别做什么？
4. 为什么不能只执行 `mov al, 0x02` 后直接写端口？
5. 为什么必须避免把端口 `0x92` 的 bit 0 写成 `1`？
6. 即使本机 QEMU 复位时已有 `A20=1`，bootloader 为什么仍应主动确保它开启？
7. 为什么 A20 关闭时，本课的 `Hello` 仍然能够正常输出？
8. A20 gate 与分段地址计算分别发生在地址形成链路的哪一层？

## 完成标准

- `make check-a20` 报告 `A20=1`。
- 能用二进制解释 `0xfe` 和 `0x02` 的作用。
- 能解释 A20 关闭时的 1 MiB 地址回绕。
- 原有字符串、调用栈、段寄存器与启动扇区测试全部回归通过。
