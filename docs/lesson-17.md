# 第 17 课：阶段考试 —— 你是否真正理解了启动、地址与执行环境

这不是一次寄存器默写，也不要求重新跑一遍所有命令。考试只判断三件事：

1. 能否从输入推出结果，而不是凭印象背结论。
2. 能否把现象沿因果链定位到正确层次。
3. 能否区分“暂时能运行”和“机制已经完整”，并判断下一阶段真正缺少什么。

本章不修改代码、不新增验收命令。答案写在 [第 17 课答题记录](../notes/note-17.md)。

## 考试方式

分成两遍：

- **第一遍：独立作答。** 不打开前面讲义，不运行 QEMU/GDB，不搜索。不会就写“不确定”，并保留原始答案。
- **第二遍：导师审阅后取证。** 只针对暴露出的薄弱点查源码、反汇编或官方资料，在答题记录的“审阅后修正”中补充，不覆盖第一遍答案。

建议第一遍控制在 60–90 分钟。完整分数是 100 分：

| 部分 | 重点 | 分值 |
|---|---|---:|
| A. 判断并解释 | 基础概念、地址与 CPU 状态是否稳固 | 40 |
| B. 因果链与诊断 | 能否从现象追到机制并判断 C 前边界 | 60 |

只写“对/错”不能得满分。结论正确但原因错误，说明还没有真正理解。

## A. 判断并解释（20 × 2 = 40 分）

每题先写“正确/错误”，再用 1–3 句话说明 CPU、工具或地址转换实际做了什么。

**A1.** `org 0x7c00` 会命令 BIOS 把 boot sector 加载到物理地址 `0x7c00`。

**A2.** 实模式中两个不同的 `segment:offset` 可以指向同一个物理地址。

**A3.** `LGDT [gdt_descriptor]` 执行完毕后，CPU 就已经进入保护模式。

**A4.** 把 `CR0.PE` 设为 1 后，不经过控制转移，下一条指令就必然按新 32 位 code descriptor 执行。

**A5.** long mode 基本忽略普通段的 base/limit，因此 64 位内核可以完全删除 GDT。

**A6.** `CR3=0x1000` 表示 CPU 下一条指令要从地址 `0x1000` 开始执行。

**A7.** 设置 `CR0.PG=1` 后，CPU 可以等到下一次 far jump 才开始使用页表。

**A8.** 如果 ELF 把 `.text` 链接在 0，但 raw bytes 被加载到 `0x10000`，只含相对跳转的短小载荷仍可能恰好运行。

**A9.** 当前低 2 MiB 恒等映射下，C 中的空指针解引用一定会触发 `#PF`。

**A10.** RISC-V 没有 GDT，因此它无法像 x86 一样隔离用户态与内核态。

**A11.** 执行 `CLI` 后，外部中断、除零、非法指令和缺页异常都会被禁止。

**A12.** linker script 中的 `ENTRY(kernel_start)` 会在输出文件开头生成一条跳转到 `kernel_start` 的机器指令。

**A13.** `objcopy -O binary` 得到的 `kernel.bin` 仍包含 ELF header、entry point 和 symbol table，只是文件扩展名改变了。

**A14.** 恒等映射表示某段范围内的 linear address 与最终 physical address 数值相同；它不表示这些字节在 ELF 或磁盘镜像中的 file offset 也相同。

**A15.** 当前 `RSP=0x90000` 且低 2 MiB 已映射，因此栈越界时页表一定会立即报告错误。

**A16.** `CALL` 会把返回地址压栈；`RET` 从栈中取回该地址，因此一次正确返回后 stack pointer 应恢复到调用前的位置。

**A17.** 打开 A20 会把 CPU 从 16 位实模式切换到 32 位保护模式。

**A18.** selector `0x18` 在 `TI=0、RPL=0` 时选择 GDT 的第 3 项，因为 `3 << 3 = 0x18`。

**A19.** 只要把 `EFER.LME` 置为 1，CPU 就会立即开始执行 64 位指令，不再需要分页和 64 位 code descriptor。

**A20.** `RFLAGS.IF=0` 可以阻止可屏蔽外部中断，但不能阻止同步异常，因此它不能替代一张有效 IDT。

评分方式：判断 0.5 分，原因 1.5 分。原因必须指出具体机制，不能只改写题目。

## B. 因果链与诊断（6 × 10 = 60 分）

### B1. 从 reset 到 `kernel_start`

用不超过 12 个箭头写出完整控制流。至少覆盖：

- CPU/BIOS/boot sector/独立载荷分别何时获得控制权。
- 实模式、保护模式、long mode 的切换点。
- 内核何时被读入内存，页表何时开始参与取指。
- 哪两次控制转移会重载 `CS`，哪一次不会。

评分关注事件顺序和依赖关系；少写一个固定地址不会扣分。

### B2. 同一个入口字节为什么有五个位置

解释同一条 `kernel_start` 指令为何同时位于：

```text
kernel.elf file offset   0x1000
ELF VMA/LMA              0x10000
kernel.bin file offset   0x0000
os.img file offset       0x0200
guest physical/linear    0x10000
```

不能只复述数值；要说明 ELF header、`objcopy`、磁盘 LBA、BIOS loader 和恒等映射各自造成了哪一次坐标变化。

### B3. 只看到 `HelloPTL`，没有最后的 `K`

假设 bootloader 仍能输出到 `L`，但载荷没有输出 `K`。列出至少四个不同层次的可能原因，并给出你的排查顺序。候选层次可以包括：

- 磁盘镜像内容。
- BIOS 加载结果。
- 页表/执行模式。
- 跳转目标。
- 载荷机器码。
- ELF 与 raw binary 构建管线。

每一步必须写“查看什么证据”和“该证据能排除什么”，不能只罗列命令名。

### B4. 开启分页后立即重启

某次修改后，CPU 在执行 `mov cr0, eax` 打开 `CR0.PG` 后立刻重启。解释一条完整的可能因果链：

```text
page-table mapping 错误
  → 下一次取指发生什么
  → 产生哪类异常
  → 为什么当前 IDT 无法处理
  → 为什么最终表现为重启而不是错误消息
```

再说明：如果已经有正确 IDT 和 `#PF` handler，诊断能力会发生什么变化？

### B5. ELF 检查失败，运行却仍然成功

假设出现下面的组合：

```text
make check-kernel-elf     失败：entry/.text/symbols 从 0 开始
make check-kernel-entry   通过：HelloPTLK，RIP=0x1000e
```

解释这两个结果为什么可以同时成立。答案至少串起：linker metadata、`objcopy`、bootloader 固定加载/跳转地址、相对控制流，以及为什么加入 C 或绝对 symbol reference 后不能继续依赖这种巧合。

### B6. 第一段 C 代码“能跑”与“内核已准备好”

下一课准备从汇编入口调用一个最小 C 函数：它不使用全局变量，只输出一个字符，然后停在循环中。

回答两部分：

1. 为了让这一次最小调用成立，构建与入口至少要满足哪些条件？从 target toolchain、object/linker、调用 ABI、栈和载荷大小中选择关键项说明。
2. 为什么没有 IDT、没有 `.bss` 清零、没有 stack guard、没有内存图，并不一定阻止这一个极小函数立刻运行，却仍然意味着“内核环境不完整”？分别给出一个以后会出问题的场景。

## 评分标准：什么叫真正理解

导师不会按关键词机械计分，而是看四个层级：

| 层级 | 表现 |
|---|---|
| 只记名字 | 能说出 `CR3/PML4`，但说不出它们控制什么 |
| 能描述机制 | 能说明页表根、trap 入口、返回 PC 等硬件角色 |
| 能建立因果链 | 能从错误状态推出异常、诊断证据和修复位置 |
| 能综合 | 面对新现象时，能区分工具链、加载、地址转换、异常处理和 ABI 的责任边界 |

分数解释：

- **85–100**：启动、地址转换与执行环境已经形成稳定模型，可以进入 C 主线。
- **70–84**：整体理解成立，针对错题做一次定向复盘后进入 C。
- **50–69**：存在一到两个断裂层次，需要回看对应章节并口头复述。
- **低于 50**：不要继续堆新机制；先重建 reset→load→translate→trap 的主因果链。

考试目的不是卡住进度。它只负责让我们知道：下一阶段哪些硬件细节可以放心交给脚手架，哪些概念还需要在 C 内核里再次验证。
