# 第 2 课：构造 512 字节启动扇区

## 本课只证明一个契约

传统 BIOS 选择软盘启动后，会检查第一个 512 字节扇区末尾的启动签名，把这个扇区读入内存，并把控制权交给它。我们的目标不是背诵这个说法，而是证明磁盘文件的 512 字节确实原样出现在 guest 内存的 `0x7c00..0x7dff`。

本课仍不打印字符，不读取第二个扇区，也不切换 CPU 模式。

## 先理解三条 NASM 指令

如果此前没有使用过 NASM，先阅读 [NASM 与 x86 寄存器入门](reference/assembly-basics.md) 的第 1-3 节；下面不会假定你已经熟悉汇编器语法。

- `bits 16`：按 16 位代码规则编码指令。
- `org 0x7c00`：告诉 NASM 这段平坦二进制预计从地址 `0x7c00` 执行；它不会自动向文件前面填充 `0x7c00` 个字节。
- `jmp $`：跳回当前指令，形成稳定的无限循环，方便 GDB 捕获。

NASM 的 `-f bin` 直接产生平坦机器码，不包含 ELF 头、节表或重定位信息。[NASM `bin` 格式文档](https://www.nasm.us/doc/nasm09.html)

## 红灯：先观察失败

当前 `boot/boot.asm` 故意缺少填充和签名。运行：

```sh
make check-boot
```

它应该报告文件不是 512 字节。先把这条失败信息记入学习记录，这说明测试真的能捕获错误。

## 练习：补齐两个 TODO

编辑 `boot/boot.asm`：

1. 用 `times count db 0` 把签名前的内容填充到 510 字节。
2. 用 `dw value` 写入 16 位启动签名 `0xaa55`。

你需要自己用 `$`、`$$` 写出 `count` 表达式。完成后再次运行：

```sh
make check-boot
```

通过条件是文件恰好 512 字节，而且偏移 510、511 的两个字节依次为 `55 aa`。注意源代码里的 word 是 `0xaa55`，文件中的字节顺序却是 `55 aa`。

脚本还会比较：

```text
build/boot.bin
memory[0x7c00..0x7dff]
```

只有 512 字节完全相同时才会打印 `identical`。实验结束后在终端 A 按 `Ctrl-C`。

## 观察题

1. 为什么 `dw 0xaa55` 在文件末尾显示为 `55 aa`？
2. `org 0x7c00` 有没有让输出文件增加 `0x7c00` 个字节？它真正影响什么？
3. BIOS 跳转过来时，`CS:IP` 是多少？对应的物理地址是多少？
4. `cmp` 的成功为“BIOS 把启动扇区读入 0x7c00”提供了什么证据？

## 完成标准

- 经历一次预期失败，再补齐启动扇区使测试通过。
- 能解释签名的字节序和 `org` 的作用。
- GDB 在 `0x7c00` 命中，磁盘文件与 guest 内存比较完全一致。
